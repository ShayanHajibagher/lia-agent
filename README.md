# لیا — نسخهٔ آمادهٔ استقرار روی لیارا

این پوشه خودکفاست: فقط همین را آپلود/دیپلوی کن. هیچ مرحلهٔ build ندارد
(اسکریپت `build` تعریف نشده تا لیارا فقط `npm install` و بعد `npm start` را اجرا کند).

## ۱. پیش‌نیاز

- حساب لیارا و یک برنامهٔ **NodeJS** در کنسول (نامش را در `liara.json` بگذار).
- Liara CLI:

```bash
npm i -g @liara/cli
liara login

```

## ۲. تنظیم نام برنامه

در `liara.json` مقدار `app` را به شناسهٔ برنامهٔ خودت عوض کن:

```json
{ "app": "my-liyara-app", "platform": "node", "port": 3000 }
```

## ۳. متغیرهای محیطی

فایل `.env` **از قبل با کلید BoxAPI تنظیم شده** و با بسته آپلود می‌شود، پس بعد از
دیپلوی سایت فوراً با مدل کار می‌کند (حالت دمو نمی‌ماند).

- اگر نمی‌خواهی کلید داخل بسته باشد: `.env` را پاک کن و همین متغیرها را در کنسول
  لیارا (بخش Environment Variables) وارد کن. متغیرهای کنسول بر `.env` اولویت دارند.
- برای عوض کردن مدل، فقط `LIA_LLM_MODEL` را تغییر بده.

### چرا کلید ممکن است آپلود نشود؟

`.gitignore` این پروژه `.env*` را نادیده می‌گیرد و ابزار دیپلوی هم همان قواعد را
اعمال می‌کند؛ یعنی ممکن است `.env` هرگز به سرور نرسد و برنامه بی‌صدا در **حالت دمو**
بالا بیاید (پاسخ‌های آماده، بدون مدل).

برای اینکه این اتفاق نیفتد، فایل `liara.env` هم کنار `.env` هست و `server/env.mjs`
هر دو را می‌خواند. پس:

| روش | نتیجه |
|---|---|
| `liara.env` (پیش‌فرض همین بسته) | کلید با بسته می‌رود و کار می‌کند |
| متغیرهای کنسول لیارا | امن‌ترین راه؛ `liara.env` را حذف کن |

> `liara.env` را در گیت کامیت نکن (کلید داخلش است).

برای بررسی سریع بعد از دیپلوی: `https://<دامنه>/api/health` — اگر `"demo": true` بود،
یعنی کلید به سرور نرسیده است.

حداقل‌ها:

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `LIA_LLM_BASE_URL` | `https://ai.boxapi.ir/ai/v1` | درگاه مدل (BoxAPI) |
| `LIA_LLM_API_KEY` | — | کلید BoxAPI |
| `LIA_LLM_MODEL` | `gpt-6-luna` | نام مدل |
| `LIA_DEPLOY_SIMULATE` | `1` | `1` برای دمو، `0` برای اجرای واقعی پروژهٔ کاربر |

این بسته با یک `.env` آماده می‌آید که کلید مدل داخلش است، پس بعد از دیپلوی سایت
فوراً با مدل کار می‌کند و در حالت دمو نمی‌ماند. اگر نمی‌خواهی کلید داخل بسته باشد:
فایل `.env` را پاک کن و همین متغیرها را در کنسول لیارا ست کن.
اگر کلیدی نباشد، سایت بالا می‌آید و در **حالت دمو** کار می‌کند (بدون مصرف توکن).

### دیسک (برای ماندگاری داده)

فایل‌سیستم لیارا به‌صورت پیش‌فرض **read-only** است. این برنامه سشن‌ها، پروژه‌های
آپلودی و فهرست دیپلوی‌ها را در `.data` نگه می‌دارد، پس:

- **بدون دیسک**: برنامه بالا می‌آید، ولی داده در پوشهٔ موقت سیستم می‌نشیند و با هر
  ری‌استارت/دیپلوی پاک می‌شود (در لاگ هم یک هشدار روشن می‌بینی).
- **با دیسک**: در کنسول لیارا یک دیسک بساز و به مسیر `/data` وصل کن، بعد متغیر زیر را ست کن:

  ```
  LIA_DATA_DIR=/data
  ```

  از آن به بعد سشن‌ها، پروژه‌های آپلودی و فهرست دیپلوی‌ها بین دیپلوی‌ها می‌مانند.
  ۱ گیگابایت برای این پروژه کافی است؛ اگر می‌خواهی واقعاً پروژهٔ کاربران را بیلد کنی،
  بیشتر بده (وابستگی‌های هر پروژه چند صد مگابایت جا می‌گیرند).

## ۴. دیپلوی

```bash
cd ready-project
liara deploy
```

یا بدون CLI: همین پوشه را zip کن و در کنسول لیارا (استقرار > آپلود) بگذار.
لیارا خودش `npm install` را اجرا می‌کند.

## ۵. بعد از دیپلوی

| مسیر | چیست |
|---|---|
| `/` | صفحهٔ اصلی (آینهٔ liara.ir) + ویجت لیا |
| `/pricing/?lia=open` | صفحهٔ قیمت با سایدبار باز |
| `/agent/` | بخش ایجنت (چت + پروژه + دیپلوی) |
| `/panel/` | پنل جعلی برای تست راهنما |
| `/api/health` | سلامت سرویس و وضعیت مدل |

برای health check در کنسول لیارا، مسیر `/api/health` را بگذار.

### پیش‌نمایش اپ‌های دیپلوی‌شده

هر پروژه‌ای که در بخش ایجنت دیپلوی شود، روی همین دامنه آدرس واقعی می‌گیرد:

```
https://<دامنهٔ-اپ>/apps/<نام-اپ>/
```

- اپ‌های **استاتیک** از همان مسیر سرو می‌شوند.
- اپ‌های **داینامیک** (Node/Next/Python) از طریق پروکسی داخلی به پورت خودشان وصل می‌شوند.
- فهرست و وضعیت: `/api/apps` (نام، پورت، وضعیت، آدرس پیش‌نمایش).

اگر دامنهٔ اختصاصی با وایلدکارد داری، `LIA_PREVIEW_DOMAIN` را ست کن تا
`<نام-اپ>.preview.example.com` هم مستقیم کار کند. با دامنهٔ اشتراکی `liara.run`
این کار ممکن نیست، ولی مسیر `/apps/…` همیشه کار می‌کند.

> نکته: در حالت `LIA_DEPLOY_SIMULATE=1` هیچ اپی اجرا نمی‌شود؛ آدرس‌ها فقط برچسب‌اند
> و در رابط با هشدار «شبیه‌سازی» نشان داده می‌شوند.

## ۵٫۵ فایل‌های AI Studio

`src/`، `index.html`، `vite.config.ts`، `tsconfig.json` و `metadata.json` بازماندهٔ
پروژهٔ Google AI Studio هستند و **در سرو شدن سایت نقشی ندارند** (سرور از `public/`،
`agent-ui/` و `widget/` سرو می‌کند و `vite` هم در وابستگی‌ها نیست). حذفشان روی
دیپلوی اثری ندارد.

پوشهٔ `.aistudio/` حذف شده است؛ پشتیبانش در `_backup/aistudio-2026-10-23/` و متن
طرح در `docs/aistudio-plan.md` نگه داشته شد.

## ۶. نکات مهم

- **ماندگاری داده**: بدون دیسک، `.data` موقت است و با هر ری‌استارت پاک می‌شود
  (بخش «دیسک» در بالا).
- **دیپلوی شبیه‌سازی**: با `LIA_DEPLOY_SIMULATE=1` هیچ کد کاربری روی سرور اجرا نمی‌شود.
  اگر آن را `0` کنی، ایجنت واقعاً `npm install`/بیلد/اجرا را روی همین کانتینر انجام
  می‌دهد؛ برای محیط عمومی این کار را فقط با ایزوله‌سازی و سقف منابع بکن.
- **مدل**: آدرس `127.0.0.1:1234` (LM Studio) از داخل لیارا در دسترس نیست؛ از یک
  درگاه ابری استفاده کن.
- **حجم آپلود**: لیارا محدودیت حجم دیپلوی ندارد؛ `public/` (سایت آینه‌شده، حدود ۶۰
  مگابایت) را همین‌طور بگذار تا همهٔ صفحه‌ها و دارایی‌ها بالا بیایند. اگر فقط ویجت و
  بخش ایجنت را می‌خواهی، می‌توانی `public/` را خالی بگذاری؛ بقیهٔ مسیرها مستقل کار
  می‌کنند.

## ۷. عیب‌یابی

| نشانه | علت احتمالی |
|---|---|
| 502 / Bad Gateway | برنامه روی `0.0.0.0` گوش نمی‌دهد یا `PORT` را نخوانده (این پوشه درست تنظیم شده) |
| صفحهٔ 404 روی `/` | شناسهٔ برنامه در `liara.json` با کنسول یکی نیست |
| پاسخ‌های دمو | `LIA_LLM_API_KEY` ست نشده یا درگاه در دسترس نیست |
| دیپلوی طولانی | `LIA_DEPLOY_SIMULATE=0` با منابع کم، یا نصب وابستگی‌های سنگین پروژهٔ کاربر |
